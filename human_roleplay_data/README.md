# Human Role-Play Authorization Data

This directory contains the source-data-only, deidentified questionnaire
release used for the paper's human role-play analysis. It contains 584
participants and 1,752 paired participant-method judgments. Each participant
was assigned one household persona and evaluated method-name-masked
consequences from MPC, HEMA, and EnergyBridge.

The release intentionally contains no precomputed result table. Acceptance
rates, statistical tests, figures, LLM outputs, and prior benchmark summaries
must be generated by the reviewer from the released microdata or from a new
benchmark run.

## Quick verification and analysis

Run from the repository root:

```bash
python human_roleplay_data/scripts/validate_release.py

python human_roleplay_data/scripts/reproduce_analysis.py \
  --output-dir generated_results/human_roleplay \
  --bootstrap-replicates 10000 \
  --bootstrap-seed 1
```

The first command validates privacy invariants, pairing, value ranges, record
counts, checksums, and archive contents. The second writes newly computed
human-only acceptance, satisfaction, paired-comparison, omnibus-test, and
age-band tables to the ignored `generated_results/` directory.

## Study design

Respondents adopted an assigned household persona and evaluated the same
persona, event context, question wording, and method-name-masked consequence
format used by the LLM evaluator. Plan labels were decoded only for analysis:

- Plan A: MPC
- Plan B: HEMA
- Plan C: EnergyBridge

The released outcomes are:

- `acceptance`: binary event authorization, 1=accept and 0=reject;
- `satisfaction_score`: outcome satisfaction on the original 0-5 slider.

The participant ID exists only to preserve the within-participant pairing
across the three methods. It is a new public ID, not an original survey
identifier.

## What can be regenerated

The public microdata are sufficient to regenerate:

- human acceptance rates and Wilson intervals;
- persona-level paired method comparisons;
- satisfaction summaries;
- Cochran Q and exact McNemar tests;
- released age-band summaries.

The public microdata are not sufficient by themselves to regenerate:

- the LLM side of human-LLM alignment;
- sensitivity analyses based on response duration or private QC flags;
- gender, city, province, or exact-age summaries.

To compare the human data with a newly generated LLM evaluation, prepare a CSV
with one row per method and the columns
`method,llm_accepted,llm_trials`, then pass it explicitly:

```bash
python human_roleplay_data/scripts/reproduce_analysis.py \
  --output-dir generated_results/human_llm_alignment \
  --llm-counts generated_results/new_llm_acceptance_counts.csv
```

No historical LLM counts are bundled.

## Provenance boundary

`scripts/build_public_release.py` documents the transformation but requires
the private transfer ZIP, which is intentionally excluded from Git. Rebuilding
rekeys participant IDs, so the result is statistically equivalent but not
byte-identical at the ID level.

The private ZIP, source-to-release mapping, IP addresses, timestamps, response
durations, free text, exact ages, participant-level geography, and
participant-level gender must never be committed or attached to an anonymous
release.

The review artifact does not encode institutional or approval identifiers.
Consent, ethics, and data-license terms for any later public distribution must
be documented separately from the deidentified records.
